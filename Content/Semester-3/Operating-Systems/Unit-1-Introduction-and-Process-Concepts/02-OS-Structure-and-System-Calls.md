## OS structures
- **Simple/monolithic kernel:** the entire OS runs in one big kernel address space (classic Unix, Linux). Fast, because components call each other directly, but a bug in a driver can crash everything.
- **Layered approach:** the OS is split into layers, each using only the one below (hardware at layer 0). Easy to debug, but a request may pass through many layers, and designing the layers is hard.
- **Microkernel:** only the minimum (low-level memory, scheduling, inter-process communication) stays in the kernel; file systems, drivers and networking run as user-level servers. More reliable and portable, but message passing adds overhead. Examples: Minix, QNX, Mach.
- **Modular kernel:** a core kernel plus **loadable modules** (Linux modules, drivers loaded on demand).
- **Hybrid:** mixes ideas (Windows NT, macOS).
- **Virtual machine:** a hypervisor shares the hardware among several guest OSs.

## System calls
A **system call** is the programmatic interface by which a user program asks the kernel for a service. Programs usually call a library wrapper (the C library's `write()`), which puts the call number in a register and executes a **trap** instruction to enter kernel mode. After the kernel finishes, control returns to the program.

Parameters can be passed in registers, in a memory table (address of table in a register) or on the stack.

## API versus system call
Programmers normally use an **API** (POSIX, Win32, the C library). The API function may make zero, one or several system calls underneath. Using an API makes programs portable.

## Interrupts, traps and exceptions
- **Interrupt:** an asynchronous signal from hardware (timer, keyboard, disk). The CPU saves its state, runs an **interrupt service routine (ISR)** found through the **interrupt vector**, then resumes.
- **Trap (software interrupt):** triggered by the program to enter the kernel (system call).
- **Exception:** triggered by an error such as divide-by-zero or an invalid memory access.

## Booting
Power-on runs firmware (BIOS or UEFI), which finds the **boot loader** (GRUB, Windows Boot Manager), which loads the kernel, which starts the first process (`init` or `systemd`).

Q: What is a system call?
A: It is the controlled interface through which a user program requests a service from the kernel, such as opening a file or creating a process. It causes a switch from user mode to kernel mode.
Q: What is the difference between a monolithic kernel and a microkernel?
A: A monolithic kernel runs all OS services in kernel space for speed. A microkernel keeps only the minimum in kernel space and runs other services as user-level servers, improving reliability but adding message-passing overhead.
Q: What is the difference between an interrupt and a trap?
A: An interrupt is an asynchronous signal from hardware. A trap is synchronous and generated by the running program, such as a system call or an exception.
Q: What does the interrupt vector contain?
A: A table of addresses of the interrupt service routines, indexed by interrupt number.
Q: Why do programs use an API instead of raw system calls?
A: An API such as POSIX hides the details, makes code portable across systems, and may combine several system calls.

## High
P: Compare a monolithic kernel with a microkernel. Give one advantage and one disadvantage of each and name an example operating system.
A: Monolithic kernel: all OS services (scheduler, file system, drivers) run in kernel space as one big program. Advantage: fast because calls are direct function calls. Disadvantage: a bug in any driver can crash the whole system. Example: Linux.
Microkernel: only the minimum (scheduling, IPC, basic memory) runs in kernel space; file systems and drivers run as user-space servers. Advantage: more reliable and secure because a failing server does not crash the kernel. Disadvantage: slower because services communicate by message passing. Example: MINIX or QNX.

## Advanced
P: A C program calls printf("hi") and the text appears on screen. Describe step by step how this reaches the kernel as a system call, and explain why a system call costs more than a normal function call.
A: 1) printf is a library function in user space; it formats the text into a buffer.
2) When the buffer is flushed the library calls write(1, buffer, length).
3) The write wrapper puts the system call number and arguments in registers and executes a trap (software interrupt / syscall instruction).
4) The CPU switches to kernel mode and jumps to the kernel system call handler through the trap table.
5) The kernel validates the arguments, writes to the terminal device driver, and returns a result.
6) The CPU switches back to user mode and printf returns.
A system call is costlier because of the mode switch, saving and restoring registers, argument validation, and possible cache and TLB effects, whereas a normal call is just a jump within the same mode.
